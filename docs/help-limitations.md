# 利用者向けヘルプ: 送れないキーとバックグラウンドの制約

この文書は利用者向けヘルプ（設定 > ヘルプ「送れないキーとバックグラウンド」）の元原稿である。
アプリ内の文言は `App/Settings/HelpView.swift` にあり、内容を変えるときは両方を直す。
設計上の根拠は [input-design.md 4.3](input-design.md) と [architecture.md 10](architecture.md) にある。

## 1. iPadOS が先に使うキー

物理キーボードの一部の組み合わせは iPadOS がシステム操作に使うため、アプリには届かず、
Windows へも送れない。iPad の Command キーは Windows キーとして送るので、
**Windows キーを含むショートカットの多くがここに当たる**。

| 押したキー | iPadOS での動作 | Windows で本来起きること | 代わりの操作 |
|---|---|---|---|
| Command+Tab | App 切り替え | Win+Tab（タスクビュー） | キーバーの Win を押してから Tab |
| Command+Space | Spotlight | Win+Space（入力言語の切替） | キーバーの Win を押してから Space |
| Command+H | ホーム画面へ | Win+H（音声入力） | キーバーの Win を押してから H |
| Command+Shift+3 / 4 | スクリーンショット | — | Windows の画面の切り取りは、キーバーの Win と Shift を押してから S |
| Command を長押し | ショートカット一覧やメニューバー | — | — |
| Globe（地球儀）キーとの組み合わせ | iPadOS のショートカット | — | Windows へは送らない |
| Control+Space（設定による） | iPadOS の入力ソース切替 | Ctrl+Space | キーバーの Ctrl を押してから Space |
| Caps Lock（設定による） | iPadOS の英字入力切替 | Caps Lock | iPadOS の「設定 > 一般 > キーボード > ハードウェアキーボード」で Caps Lock による入力切替をオフにする |

- 上の表は iPadOS の既定の割り当てによる。iPadOS の設定やキーボードの種類、iPadOS の版によって
  増減することがある。手元の実機で網羅的に記録したものではない（test-plan.md の KEY-RESERVED-01 が未了）。
- 「英数」「かな」はアプリが受け取り、それぞれ Windows の「無変換」「変換」として送る。
  Windows 側でこの 2 つに IME のオフ/オンを割り当てる設定は、4 節を参照。
- Ctrl+Alt+Del は、キーバーの Ctrl と Alt を押してから Del を押すとリモートへ送られ、Windows の
  セキュリティ画面（ロック、サインアウト、パスワードの変更、タスク マネージャー）が出る（2026-10-07、Windows 11 で確認）。
  Windows の「リモート デスクトップ接続」で知られる Ctrl+Alt+End は、そのクライアントが手元で Ctrl+Alt+Del に
  置き換えるショートカットで、mRemote から送ってもセキュリティ画面は出ない。

### キーバーの修飾キー

ソフトウェアキーボードのキーバーにある Ctrl / Alt / Shift / Win は押すたびに状態が変わる。

| 状態 | 表示 | 意味 |
|---|---|---|
| オフ | 通常 | 何もしない |
| 次の 1 キー | 強調 | 次に押したキー 1 つにだけ付く |
| 固定 | 鍵のアイコン | もう一度押すまで、以後のキーすべてに付く |

ラップトップ姿勢のフル PC キーボード（iPhone Duo など）には Win キーがあり、物理キーボードの予約に当たらない。
軽く押すと Win 単体、0.5 秒以上押すと固定になる。

## 2. バックグラウンドに移ったとき

iOS / iPadOS は、画面に出ていないアプリの通信を長く続けることを保証しない。mRemote はこれを前提にしている。

- **別のアプリに切り替える、ホーム画面に戻る、画面をロックする** と、押していたキーとボタンはすべて離され、
  音声は止まる。リモートの画面はその時点のまま止まる。
- 数十秒から数分で、OS が接続を閉じることがある。戻ったときに切断されていれば、画面に「切断されました」と
  理由が出るので、「再接続」を押す。設定の「自動再接続」を「する」にしていれば自動でつなぎ直す。
  ただし、別の端末が同じユーザーで接続して引き継いだ場合は、取り返し合いにならないよう自動では再接続しない。
- 音声はバックグラウンドでは再生しない（バックグラウンド音声の権限は使わない）。
- 長い処理をリモートで動かしたままにする場合は、Windows 側のセッションに任せてよい。
  RDP の切断はサインアウトではないので、再接続すると同じデスクトップに戻る
  （Windows のポリシーで切断セッションの制限時間が設定されている場合を除く）。

### 複数のセッション

- 入力と音声は、画面に出ているセッション 1 つだけに届く。裏のセッションの音は鳴らない。
- 裏のセッションも接続は保ち、表に出すとそのまま使える。ただしアプリ自体がバックグラウンドに
  移ったときは、上と同じく OS が接続を閉じることがある。

## 3. 関連する制約

- クリップボードは文字のみ。コピー/貼り付けの操作をしたときだけ転送し、常時監視はしない。
- iPadOS のキーリピート設定はアプリから読めないため、押し続けたときのリピートはアプリ側の既定値で動く。

## 4. Windows 側の IME 設定（英数/かなで IME をオン/オフ）

Mac と同じ感覚で「英数」で IME オフ、「かな」で IME オン にするには、Windows の Microsoft IME で
無変換/変換キーに割り当てる。

1. Windows の「設定 > 時刻と言語 > 言語と地域」で 日本語 の「…」から「言語のオプション」を開く。
2. 「Microsoft IME」の「…」から「キーボード オプション」を開き、「キーとタッチのカスタマイズ」を選ぶ。
3. 「キーの割り当て」をオンにし、「無変換キー」を「IME-オフ」、「変換キー」を「IME-オン」にする。
4. 設定はサインインし直した後のセッションから効く。
