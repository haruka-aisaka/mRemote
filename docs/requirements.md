# 要件定義

## 1. プロダクト目標

JIS キーボードとマウスを接続した iPad を、Windows の実用的なリモート端末として使えるようにする。iPadOS 側の物理キーボード IME を経由せず、Windows 側 IME を英数/かなキーで自然に制御できることを最優先する。

## 2. 対象範囲

### MVP に含む

- 保存可能な複数の RDP 接続先
- NLA/TLS を用いた Windows への RDP 接続
- 画面描画、ローカル拡大縮小/パン。server が DISP を提供する場合は remote 解像度も追従
- 物理キーボードの key-down/key-up 転送
- 英数 (`LANG2`) → 無変換、かな (`LANG1`) → 変換の転送
- マウスの移動、左/右クリック、ドラッグ、縦/横スクロール
- スクロール方向反転のグローバル設定と接続別上書き
- 複数セッションの同時接続と切替
- リモート音声の端末再生
- プレーンテキストクリップボードの双方向転送
- 接続先一覧、接続編集ダイアログ、グローバル設定、全画面セッション UI
- 認証情報の Keychain 保存、サーバー証明書の確認
- 前景復帰時の切断検出と手動/自動再接続

### 後半フェーズに含む

- ソフトウェアキーボードの「ローカル IME」と「ホスト IME」モード
- Ctrl/Alt/Shift/Win、変換/無変換などの画面内キー
- キーのラッチ/ワンショット切替、リモートのセキュリティ画面などの定型操作

### MVP に含まない

- SSH（ただし拡張可能な境界は初期実装に含む）
- カメラ、マイク、USB、ドライブ、プリンター、スマートカードのリダイレクト
- 画像/HTML/ファイルのクリップボード転送
- RD Gateway、RemoteApp、管理者セッション
- バックグラウンドでの無期限接続保証
- iPadOS の予約ショートカットをすべて横取りすること

## 3. 機能要件

要件 ID は実装チケットとテストケースの共通キーとして使う。

| ID | 要件 | 優先度 |
|---|---|---|
| CON-01 | 接続先を追加、編集、複製、削除できる | Must |
| CON-02 | ホスト名/IP、ポート、ユーザー、ドメイン、資格情報、画面、音声、クリップボード、キーボード設定を保存できる | Must |
| CON-03 | DNS、TCP、TLS、認証、証明書など接続失敗の段階と再試行方法を表示する | Must |
| CON-04 | ユーザーが明示的に信頼していない不一致/自己署名証明書を無言で受け入れない | Must |
| SES-01 | 最低 2 つの RDP セッションを同時に接続し、任意に切り替えられる。3 つを初期目標とし、端末別保証数は実測後に決める | Must |
| SES-02 | 一覧へ戻っても明示切断までは前景中の接続を維持する | Must |
| SES-03 | セッションごとの接続中/再接続中/切断/エラー状態を表示する | Must |
| SES-04 | 1 セッションの I/O stall、回復可能な protocol error、通常負荷が他セッションや UI を停止させない | Must |
| DSP-01 | リモート画面をアスペクト比維持で Fit/100% 表示できる | Must |
| DSP-02 | ピンチ拡大、パン、端末回転、表示領域変更後も座標変換が正しい。DISP 非対応 server は local scaling または再接続で扱う | Must |
| DSP-03 | 更新矩形だけを描画し、UI メインスレッドをネットワーク/デコード処理でブロックしない | Must |
| KEY-01 | 物理キーの down/up をホストへ送る | Must |
| KEY-02 | 英数 `0x91` を無変換 scan code、かな `0x90` を変換 scan code として送る | Must |
| KEY-03 | 対象の物理 key event を消費し、物理キーボード操作を iPadOS IME に処理させず、候補/入力ソース UI を表示させない | Must |
| KEY-04 | UIKit と GCKeyboard の重複イベントを二重送信しない | Must |
| KEY-05 | フォーカス喪失、バックグラウンド移行、切断時に押下中キーを解放する | Must |
| KEY-06 | iPadOS が予約するキーには画面内代替操作を用意できる設計とする | Should |
| PTR-01 | マウスの移動、左/右クリック、左/右ドラッグを送る | Must |
| PTR-02 | 縦/横スクロールを送り、方向を反転できる | Must |
| PTR-03 | 拡大/パン状態にかかわらずリモート座標へ正しく写像する | Must |
| AUD-01 | `rdpsnd` 音声を端末の現在のオーディオ出力へ再生する | Must |
| AUD-02 | 音声ルート変更、中断、消音、セッション切替を安全に処理する | Must |
| CLP-01 | ユーザー操作を起点にローカルのプレーンテキストをリモートへ送れる | Must |
| CLP-02 | リモートのプレーンテキストをローカルへコピーできる | Must |
| CLP-03 | クリップボードの反射ループと過剰なペーストボード読み取りを防ぐ | Must |
| UI-01 | 起動時に接続先一覧を表示し、追加とグローバル設定へ進める | Must |
| UI-02 | 接続設定を iPad ではシート/ポップオーバー、iPhone では適応的シートで編集する | Must |
| UI-03 | セッション画面は全画面とし、フローティングボタンから一覧、切替、入力、設定、切断へ進める | Must |
| SFT-01 | ソフトキーボード利用時にローカル IME/ホスト IME を選択できる | Later |
| SFT-02 | ホスト IME モードで変換/無変換と Ctrl 等の画面内キーを使える | Later |
| EXT-01 | 接続先、セッション、入力の上位層が FreeRDP の型へ直接依存しない | Must |
| EXT-02 | 将来 SSH の設定フォーム、端末ビュー、セッション実装を追加できる | Must |

## 4. 非機能要件

| 分類 | 要件/初期目標 |
|---|---|
| 対応 OS | iPadOS/iOS 17.0 以上。iPad を主対象、iPhone は同一機能を適応レイアウトで提供 |
| 安全性 | 資格情報を平文ファイルへ保存しない。ログにパスワード、クリップボード本文、画面内容を出さない |
| 応答性 | ローカル入力の受信から FreeRDP 送信キュー投入まで p95 16 ms 以下（ネットワーク往復を除く） |
| 描画 | 60 Hz 端末で UI 操作を維持し、フレームが間に合わない場合は古い中間フレームを破棄して最新状態へ追従 |
| 安定性 | 回復可能な protocol error/I/O stall を session 内へ隔離する。native memory fault の process 隔離はできないため、更新・境界検証・sanitizer で低減 |
| リソース | 2 セッションを必須、3 セッションを目標として各 1920×1080 で 30 分測定し、接続前 budget とメモリ警告時の縮退を確認 |
| 観測性 | 接続 ID、状態遷移、エラー分類、性能カウンターを OSLog へ記録。秘密値と本文は除外 |
| アクセシビリティ | 接続一覧・設定・フローティングメニューを VoiceOver/Dynamic Type で操作可能にする |
| ローカライズ | UI 文言を String Catalog に分離。初期は日本語、英語追加を妨げない |

性能値は製品 SLA ではなく、スパイクと実機測定を合否判定可能にする初期値である。

## 5. 主要ユースケース

### UC-01: 保存済み Windows へ接続

1. ユーザーが接続先一覧から項目を選ぶ。
2. 未保存なら資格情報を入力する。
3. 証明書が未確認なら、ホスト名、発行者、フィンガープリントを確認する。
4. 全画面セッションへ遷移する。
5. 失敗時は段階別エラーを表示し、設定編集または再試行を選べる。

### UC-02: 英数/かなで Windows IME を切り替える

1. RDP 描画面が first responder になる。
2. 英数またはかなの down/up が HID usage として届く。
3. 入力調停器が経路の重複を排除する。
4. 英数を無変換、かなを変換の RDP scan code に写像する。
5. Windows が無変換/変換として受信する。対応する host 側 IME 割当が設定済みなら IME 状態が切り替わり、iPadOS 側には未確定文字列を作らない。

### UC-03: 別セッションへ切り替える

1. フローティングボタンからセッションスイッチャーを開く。
2. 接続中の別セッションを選択する。
3. 現セッションの local 押下状態を即時 clear し、送信可能なら key/button up を順序付きで best effort 送信する。
4. 選択先の最新フレームを表示し、入力フォーカスと音声の主セッションを移す。

## 6. 受入条件の要約

- Phase 0 で端末機種、OS build、キーボード機種/接続方式、関連設定を記録した基準環境を作り、英数/かなの各 10 回の down/up が Windows 側で無変換/変換として各 1 回ずつ認識され、欠落・二重送信・押下残りがない。既存画像の `UIKit+GC` 結果もこの環境で再取得する。
- 日本語入力中に英数/かなを操作しても iPadOS の変換候補/入力ソース UI が出ず、ローカル入力ソースによる文字列が RDP 入力へ混入しない。
- マウスの左右クリック、ドラッグ、縦横スクロールが成立し、反転設定が次の接続にも保持される。
- 2 セッションを同時接続し、切替後も各デスクトップとクリップボードチャネルが継続する。3 セッションは基準端末での初期性能目標とする。
- リモート音声が再生され、イヤホン接続/切断や電話等のオーディオ中断後に復帰できる。
- ローカル/リモート双方の日本語プレーンテキストをコピーでき、OS のペースト許可を不必要に繰り返し要求しない。
- 不正な証明書を無言で永続信頼せず、保存パスワードがアプリコンテナの平文データに存在しない。
