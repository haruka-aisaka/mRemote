# モバイル回線での通信量を減らす（無音の音声を止める・省データ）

## 背景
モバイル回線では「画質: 自動」が 15fps・1.5Mbps に下げているが、測ってみると通信量の大半は音声だった。
2848×2004 で測った受信量（シミュレータ、2026-10-25）:

| 場面 | 高画質（60fps） | 低画質（15fps） |
|---|---|---|
| 静止画面 | 約 50〜90 kbps | 約 40〜70 kbps |
| 動きのある画面 | 約 560 kbps | 約 430 kbps |
| 同上・1600×1200 のとき | 約 130 kbps | 約 120 kbps |
| 音声（非圧縮 PCM 48kHz ステレオ） | 約 1,500 kbps | 約 1,500 kbps |

しかも Mac で一度音が鳴ると、そのあと無音になっても音声を送り続ける（Mac の出力装置が動いている間ずっと）。
画面は画質設定より解像度（画素数）の影響が大きい。

## 現状の挙動
- 音声は常に非圧縮で送る。Mac で音が鳴ったあとは、無音でも約 1,500kbps 流れ続ける
- モバイル回線・低データモードのとき、「画質: 自動」は 15fps・1.5Mbps に下げる（つないだまま切り替わる）
- 画面は、頼んだ解像度・拡大率どおりの画素数（Retina なら縦横 2 倍）で送る

## 変更後の挙動

### 1. 無音のときは音声を送らない（Mac 側のサーバ。常に有効）
- Mac で音が鳴っていない間は、音声を送らない。鳴り始めたら送り始める
- 聞こえ方は変わらない（鳴り始めが遅れたり、頭が欠けたりしない）
- Windows など他のサーバには関係しない

### 2. 「省データ」設定を足す
- 接続先の設定（編集画面）とセッションのメニューに「省データ」を足す。選択肢:
  - **自動**（既定）: モバイル回線か低データモードのときだけ有効
  - **常に**
  - **使わない**
- メニューで変えたら、その接続先の設定として保存する（2026-10-25-session-settings-writeback.md と同じルール）
- 自動のとき、つないだまま回線が変わったら（Wi-Fi ⇄ モバイル回線）その場で切り替わる。画面の大きさは数秒で、
  音声は次に送る音から変わる
- セッションのメニューに、いま有効かどうかを出す（例:「省データ: 自動（モバイル回線のため有効）」）
- 今の「画質」はそのまま残す（省データとは別に選べる。画質を保ったまま省データだけ使うこともできる）

省データが有効なとき、次の 2 つが働く。

**音声を AAC で送る（Mac のとき）**
- Mac・iPhone が標準で持つ AAC で圧縮して送る。約 1,500kbps → 約 96kbps
- 音楽でも聞き分けにくい程度の音質。音の遅れが 0.1 秒ほど増える
- Windows のときは今までどおり（非圧縮）

**画面を等倍の画素数で送る（Mac・Windows とも）**
- Retina（拡大率 150% 以上）で頼んでいる画面を、縦横半分の画素数・半分の拡大率で頼み、iPhone で拡大して表示する
  - 例: 2848×2004・Retina → 1424×1002・等倍。Mac の画面の広さ（ポイント）や窓の並びは変わらない
- 画素数が 1/4 になるので、動きのある画面の通信量が大きく減る（1600×1200 で測った値から、1/3 前後の見込み）
- 文字や細かい線は少しぼやける
- 拡大率 150% 未満で頼んでいる画面は変えない

## スコープ外
- HEVC など、映像のコーデックを変えること（効果を測ってから、別の変更定義書で）
- 「画質」の中身（fps・ビットレート）を変えること
- 音声の入力（マイク）
- Windows での音声の圧縮
- 通信量を数字で表示すること

## E2E テストチェックリスト
受信量は、シミュレータの mRemote の受信バイト数を測る（2848×2004、15〜20 秒）。

- ### 正常系
  - [ ] Mac で音を鳴らして止めたあと、静止画面の受信量が 150kbps 未満に戻る（今は約 2,000kbps）
  - [ ] そのあと鳴らした 997Hz の音が、周波数・SN 比・途切れなしで届く（鳴り始めも欠けない）
  - [ ] 省データ「常に」で音を鳴らすと、音声込みの受信量が 300kbps 未満で、届いた音の周波数が正しい
  - [ ] 省データ「常に」で、Mac の仮想ディスプレイが 1424×1002（等倍）になり、アプリでは画面に合わせて四隅まで映り、タップの位置が合う
  - [ ] 省データ「常に」で、動きのある画面の受信量が「使わない」のときの半分未満
  - [ ] 省データ「使わない」に戻すと、Mac が 2848×2004（Retina）に戻り、音声も非圧縮に戻る
  - [ ] 省データを編集画面とメニューで選べ、メニューで変えた値が編集画面にも出る
- ### 異常系
  - [ ] AAC を扱えないクライアント（テスト用クライアント）がつないでも、音声は非圧縮で届く
  - [ ] 表示制御チャネルのないサーバでは、省データでも画面の大きさは変わらず、落ちない
- ### エッジケース
  - [ ] 省データ「自動」で、Wi-Fi のときは無効、低データモード相当にすると（テストでは切り替えを模擬）つないだまま有効になる
  - [ ] 拡大率 100% で頼んでいる画面（1024×768 など）は、省データでも大きさが変わらない
  - [ ] 音を鳴らしたまま省データを切り替えても、音が途切れ続けたり落ちたりしない
